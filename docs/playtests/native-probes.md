# 原生引擎诊断

测试源码位于 `tests/wurst/runtime/`。普通检查仍使用 `tools\Run-WurstChecks.bat`，普通构建会清除 staging，不包含原生诊断包。

隔离试玩时，在当前 PowerShell 调用内选择一个诊断包：

```powershell
$env:WURST_NATIVE_PLAYTEST = 'TDNativeEquipmentProbe'
try {
    cmd /c "build-and-deploy-test-map.bat <NUL"
    if ($LASTEXITCODE -ne 0) { throw 'Native probe build failed' }
} finally {
    Remove-Item Env:\WURST_NATIVE_PLAYTEST
}
```

唯一 BAT 入口通过 `Sync-WurstTests.ps1 -Mode StageNative` 只纳入一个指定测试文件；构建结束立即清理 staging。编译或清理失败都禁止部署。地图名称带 `TEST-HHmm`，仍会覆盖根目录和 Test 部署图，因此完成诊断后必须再次运行普通 BAT 构建恢复正常产物。

`TDNativeEquipmentProbe`：进入仅玩家1开启的新局后输入 `-equipment`，创建两座测试塔、三件固定装备，增加测试生命和金币。32轮卸下、重装、跨塔、工人转移后，验证带装备取消升级、再次升级及最终卸装。下一tick检查真实背包句柄、攻击/攻速能力等级和原生索敌范围。任何失败停止并保留阶段；不能作为正常经济、通关或实际攻击距离测量结果。

`TDNativeWaveProbe`：仅玩家1开启的新局、没有塔时输入 `-waves`。通过真实生成计时器产生第30/31波，冻结所有敌人，先逐只清旧波、保留新波验证独立奖励，再清新波验证只结算一次。失败或完成后解除冻结并清理计时器。额外生命与人口状态不恢复，必须退出诊断局、普通构建后再开始正常试玩。TEST-0446修前失败，TEST-0455修后全流程通过；不能代替自然战斗或完整通关验证。

`TDNativeRewardProbe`：同样的新局输入 `-rewards`。逐种创建44种敌人验证身份、归属和最大生命，并检查uS12移动；然后真实背包+原生致死伤害验证同路金币、跨路/工人/Boss/卸装限制、额度截断、无击杀者和漏怪。固定随机种子验证精英绿装→蓝装的额外品质判定、掉落件数、普通掉落预算，以及Boss装备前后的相同奖励与随机序列。TEST-0523全流程PASS。测试后清理创建单位、装备和rect，但不还原生命、预算、随机状态，必须结束该诊断局再恢复普通构建。
