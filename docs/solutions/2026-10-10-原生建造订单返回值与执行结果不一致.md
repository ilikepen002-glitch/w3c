# 原生建造订单返回值与执行结果不一致

## 现象与影响

受限正常经济执行器用真实初始工人发原生建造命令，按返回 false 立即停止。连续诊断中看似不能开建，阻断了正常经济策略试玩；并非已证明玩法或经济失衡。

## 环境与证据

Windows Warcraft III 1.27a，Wurst/JASS；测试包显式 opt-in。工人 `uF01` 父 `hpea`，AHbu 建造能力、列表含 `uA11`，飞行移速 522。塔 `uA11` 为 human 建筑，50 金、0 木、1 人口，192 路径纹理。

- TEST-0259：原点 (-1664,2304)，build API false，未观察扣费/开工。
- TEST-0308：原点 point API false，未观察扣费/开工；同局人工在 (-1760,2016) 发相同 orderId 1967206705，扣 50 金、同坐标开工、人口 1/4，塔实际完成并击杀怪物。
- TEST-0323：执行器改用 (-1760,2016)，point API 返回 false，但实际已扣 50 金，当前 order 1967206705、同坐标 `CONSTRUCT_START`、人口 1。由此直接证明返回 false 与实际开工不一致。
- 0323 构建时间 2026-10-10 03:24:29（Asia/Shanghai），SHA256 `B0C325C79DDF209EF2203EC3551E0BDBCD97CA6FE2D066C48A74C123B87E193A`。

## 无效方法与根因

单凭 native 布尔值断言命令被拒绝，使已经扣费开工的实际成功请求被执行器错误终止。仅把 build API 换成 point API，没有消除返回值不可信的问题。静态可建 mask/flat 只验证占地地形，不证明原生落点吸附；原点行为与坐标对齐仍是独立边界，不能以返回值推导其根因。

已实证根因是**执行器将发令返回值当作执行结果**。这里不声称解释引擎为何返回 false，也不泛化为所有订单都会如此。

## 修复与责任归属

只修 `tests/wurst/runtime/TDNativeNormalPlayProbe.wurst`，不改生产规则。发令前登记 pending；保留返回值日志，只发单一 point API 命令，不 fallback、不重试、不补资源。匹配 owner/rawcode/位置或升级宿主的真实 FINISH 才推进；最多 20 秒未完成停止，取消/相关死亡/终局提前停止。停止后的匹配 FINISH 记录 `OBSERVED_AFTER_STOP`，时间冻结，不推进或续发。
