# Boss 阶段法术抗性未消费

## 现象与范围

`TDWaves.tdWaveBossSpellDamageTakenFactor()` 已定义 8 / 16 / 24 / 32 波的 1.00 / 0.82 / 0.68 / 0.58，但基线生产发伤路径没有消费该函数。仅凭配置与单元测试存在，不能认为后期 Boss 的阶段法术抗性已进入伤害结算。

本修复只补阶段系数消费者。经济、塔基础与技能数值、Boss 身份/父对象/护甲、近卫保护、胜利和漏怪条件保持原有定义。没有新挂符文护腕、改伤害 ID、改 DamageElement、改现有攻击类型或增加发伤段。

## 环境与历史证据边界

- 项目目标为 JASS、`wc3Patch: v1.28`，使用固定 pre1.29 标准库树 `90b45617eda50c15703e8cb2ec3241d3c7b61816`。
- 本轮只做云端源码、自动测试、地图构建和离线包验证，不启动 Warcraft III。
- 2026-10-10 的 TEST-0129 历史记录仅证明 Warcraft III 1.27.0.52240、Boss32 模板的固定输入 10，在旧 NORMAL/UNIVERSAL 通道扣 7.5，在既有双参 CHAOS/UNIVERSAL 通道扣 10。见 [伤害监听阶段记录](2026-10-10-伤害监听阶段只改事件值未生效.md)。不能外推为本轮实机结果，也不能证明 1.28 的所有原生分类。
- 本方案不假定固定 25% 原生减免，不除以 0.75，不补偿原生抗性。阶段系数是在现有通道原生结算上的额外系数；75 的既有事件量在 32 波变为 43.5。

## 排除的路径

1. 在普通 `DamageEvent.addListener` 中改事件量：固定库该阶段不会重新按事件量结算 HP，旧问题已有明确记录。
2. 将所有 `isCode` 当成法术：`Tspl`、`Eadd` 和精灵连击/处决派生伤害也使用代码发伤，不能随法术削减。
3. 用 `DamageElement` 作为持久分类：固定库会在原生事件重分类时覆盖 element；`isCode` 是先捕获、后保留的独立布尔值。
4. 新增生命值补偿、abort 后重发或额外伤害：改变原发伤/致死链，增加归属、递归和记账风险。
5. 变更英雄身份、护甲或物编挂载：会扩大到普攻及原生结算边界，超出本修复。

## 根因与实现

根因是配置没有生产消费者；同时固定库的事件阶段与代码标记不能直接当作玩法伤害分类。

- `TDEnemyMechanicState.scaledSpellAmount()` 是可测试的纯状态计算，使用记录 `link.wave` 的原始波次。只对仍活动、角色为 Boss、有效四个 Boss 波次及正数伤害应用阶段系数。
- `TDEnemyMechanicRuntime.tdEnemyMechanicScaleSpellDamage()` 复用已有 target→record 表与有效性检查。普通、精英、近卫、野生、未注册、死亡、移除、局末及失效路线目标均返回原值；不扫描世界，不新增记录生命周期。
- 已知代码法术在原 `damageTarget` 调用前缩放一次：剑刃风暴脉冲、尸爆、装备独立毒、精灵尸爆毒域、精灵雷链与火冲。
- 精灵私有 `spellDamage()` 只包装既有 `damage()`；原 `Pdam` 标记、宿主来源和双参通道保留。连击/处决 `base * extra` 仍调用原 `damage()`。
- 原生法术使用 `addUnreducedListener(2)`，只选择 `isSpell && !isCode`，在 priority 4 有效伤害记账前 `setAmount()`。固定库早期 setter 同时改变 amount/unreducedAmount，原有结算读取修改后的 amount。代码法术已在发伤点处理，监听不重复缩放。
- 独立 `tdEnemySpellResistanceListenerReady` 防止 setup→shutdown→setup 叠监听；shutdown 只撤有效记录，不复位监听标志。compiletime 不注册监听。
- 真实普攻（含 Magic 攻击类型）、`Tspl`、`Eadd`、精灵连击/处决都保持既有发伤量和通道。

## 可复用经验与可提炼技能

- 数据表已有测试不代表生产消费者存在。先找所有发伤点和最终结算使用点。
- 旧伤害引擎要核清阶段、setter 写回路径以及分类标记的生命周期。
- 玩法“法术”与引擎 `isSpell/isCode` 不同。显式处理已知 code 法术，保留代码派生普攻。
- 生命周期 once 标志应属于持续监听而非可复位的业务 ready 状态。
- 对生成 JASS 执行实际 helper 和 adapter，物编与保护系统对照基线，同时明确离线 stub 与实机的证明边界。
