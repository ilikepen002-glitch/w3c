# 装备攻速能力导致 Warcraft III 1.27a 闪退

## 现象与影响范围

用户反馈给塔装备增加射程的物品时容易退出游戏，但已经记不清具体物品与塔等级。不能据此直接把原因归为射程计算或范围圈性能问题。

本次从历史崩溃现场定位到：游戏在首次添加塔的攻速同步能力 `A129` 时崩溃。旧地图和修复前的当前构建都使用了无效的物编父 ID。具有同一错误的定义共有五个：`A124`、`A125`、`A126`、`A127`、`A129`。

当前状态（2026-10-09 更新）：源码与打包定义已修复，0009 构建的两项 artifact verifier 通过；实机三件装备共存、随兽人 I 逐阶升至碎阵剑圣 6B 保留，并完成一次混合装备卸下重装，均未崩溃。实际攻速、攻击距离及多轮装卸压力仍未验证，不能把本记录理解为所有装备闪退均已排除。

## 环境和触发条件

- 游戏：本机 Warcraft III `1.27.0.52240`，JASS 地图。
- 历史日志：游戏安装目录 `Errors/2026-10-08 22.30.27 Crash.txt`。
- 日志记载地图：`Maps/Test/MyFirstWurstMap.w3x.w3x`，不是后来部署的同名显示标题所代表的所有版本。
- 首次装备攻速大于零时，`tdSetTowerEquipmentAbilityLevel` 检测技能不存在，进入 `addPermanentAbility`，依次调用 `UnitAddAbility`、永久化、设置等级。
- 崩溃发生于第一步，不能归因于后面的设置等级或射程刷新。

## 关键证据与根因

### 从原生栈定位到具体 rawcode

只读解析本机 `Game.dll` 的 PE 节表及 JASS 原生函数注册指令序列，得到：

- `UnitAddAbility` 入口 RVA 为 `0x1FA510`。
- 日志中的 `0001:001F9559` 加上 `.text` 节 RVA `0x1000`，得到返回点 RVA `0x1FA559`。
- 该返回点紧接 `UnitAddAbility` 内 RVA `0x1FA554` 的调用，目标为内部函数 RVA `0x454EB0`。
- 对应帧指针为 `0x006FF090`；原生入口分别从 `[EBP+8]` 和 `[EBP+0xC]` 取单位、技能参数。
- 日志内存转储在 `0x006FF09C` 保存 `0x41313239`，解码为 **`A129`**。
- 顶帧 RVA `0x17BFF0` 为读取 `[ECX+0x20]`，日志 `ECX=0`，即内部空对象解引用。

这比“距离某个函数入口较近”更强：注册表、函数入口取参、直接调用返回点和栈参数形成了相互对应的证据。`DestroyImage` 与 `SetUnitAcquireRange` 的入口不同，不在这个故障原生帧中。

### 区分物编 alias 与引擎 code

从实际安装的 `war3.mpq`、`War3x.mpq`、`War3Patch.mpq`、`Patch127.mpq`、`patch.mpq` 只读提取 `Units/AbilityData.slk`。五份数据都显示：

| 字段 | 攻速能力的实际值 |
| --- | --- |
| 物编条目 `alias` | `AIsx` |
| 引擎实现 `code` | `AIas` |

所有检查的数据中都没有 `alias=AIas`。原来的 `AbilityDefinitionAIas` wrapper 使用 `AbilityIds.itemAttackSpeedBonus='AIas'`，将引擎 code 当成了可继承的父对象。打包 `war3map.w3a` 因此把上述五个能力的父 ID 写成不存在的 `AIas`。

旧图和修复前当前图的 `A129` 都有完整的 120 级 `Isx1` 数值；`A128` 的 `AIat` 父对象存在，128 级攻击数值也完整。没有发现缺级、非有限数值或需要缩减等级上限的证据。无效父对象是最符合原生空对象崩溃与实际物编数据的根因。

## 排除与无效方向

- 先前根据用户印象怀疑射程范围圈；实际范围纹理存在且可显示，当前装备视觉事件只清理圈，缺少证据把它定为本次崩溃根因。更改销毁频率不能补全无效能力父对象。
- 仅检查 Wurst 类型或装备加成聚合测试无法发现这个问题：错误字符串/rawcode 合法，且纯计算不调用游戏的物编加载器。
- 直接猜测“120 级太多”缺乏证据。等级数据完整，崩溃在能力首次创建时；先修复父对象比改平衡数值更小、更可验证。
- 历史地图名称、当前部署文件和显示标题必须分开记录，不能把历史日志当作新构建复现。

## 最简修改

在 `wurst/items/TDItemObjectGen.wurst` 的单级和同步攻速生成两处，使用现成的 `AbilityDefinitionAttackSpeedIncrease`，它继承 `AIsx`。保留所有 rawcode、等级、数值与运行时装备汇总流程，不修改依赖拷贝。

新增 `tools/VerifyEquipmentAbilityArtifact.py`，读取实际地图中的 W3A，检查：

- 五个攻速能力均继承 `AIsx`；四个固定加成分别为 0.12、0.20、0.32、0.48。
- `A129` 的全部 120 级 `Isx1` 正确。
- `A128` 仍继承 `AIat`，全部 128 级 `Iatt` 未变。

## 可复用经验与可提炼技能

1. 原生崩溃可先离线解析实际 DLL 的注册表，再把日志节偏移换算为 RVA；不需要注入或控制游戏进程。
2. 栈帧参数往往保留 rawcode；先定位具体能力再审物编，比从用户记忆泛查性能更有效。
3. 校验对象父 ID 必须使用目标游戏版本的 **alias** 集合，不能把实现 `code` 当父对象。
4. 打包检查与类型检查职责不同；前者适合验证实际继承链、等级数据及资源是否进入地图。

本机可复用只读工具与带 SHA256 的报告位于 `E:/WurstToolchain/`：`InspectWar3Crash.py`、`InspectWar3AbilityObjects.py`、`ReadWar3AbilityData.java`、`InspectWar3BaseAbilities.py`。详情见该目录 `crash-2026-10-08-223027-findings.md`。这些是本机诊断附件，本记录保留独立理解根因所需的关键证据。
