# 剑刃风暴施法与伤害范围错配

## 现象与环境

地图采用高台建塔、道路行军。碎阵剑圣（兽人 6B）的剑刃风暴以自身为伤害中心，原生 Slow 负责目标选择和自动施法入口。审查时原生施法距离为 780，运行时伤害半径却只有 200。因此能选中、触发施法的敌人可能始终处于伤害范围外。

环境为 Warcraft III 1.27.0.52240、JASS、WurstStdlib2 pre1.29。该问题与此前模型路径不存在、spin 动画表现问题独立；修复动画并不能让道路上的敌人进入原有伤害圈。

当前状态：独立方案审查 PASS WITH NOTES。0126 诊断图证明原生定向施法可执行五次有效目标伤害调用；0137 移除 forced 订单、仅将 Slow 的“总是自动施放”改为 true 后，已确认自然触发、重复施法及有效敌人伤害调用。产物检查新增 `Slo3=1` 断言并通过。spin 动画帧与每目标实际扣血仍未确认；主线程正移除预置塔及诊断日志，正式版最终检查构建尚待结果。

## 根因证据

- `TDTowerCommonData.tdOrcBladestormRadius()` 原值 200；运行时每次伤害以塔当前坐标为圆心。
- `TDTowerObjectGen` 的 Slow 施法距离原先取 6B 普攻基础射程 780，未引用风暴伤害半径。
- 固定基线的 W3E/WPM 及项目现有合法放置规则提供了独立几何交叉检查：192 占地、已有 32 安全边距、平整度与象限/出口约束下，在玩家 0 区域以 32 单位网格采样得到 2695 个合法中心。
- 对配置的出生点、五个路点和出口连接成的折线计算最短距离，距路线不超过 200 的合法中心为 0，最小距离 368；不超过 780 的中心为 1908。
- 已经实机确认合法的诊断塔位 `(-1696, 2016)`，距最近配置路段为 528。

几何统计只描述网格采样与配置折线，并非完整连续位置证明，也不是游戏引擎实际移动轨迹。即使保留这一限制，200 与典型合法塔位到道路的距离仍有显著错配。

## 排除与方案取舍

本次没有通过修改刷怪、生命、经济或加装备掩盖问题。提高普攻射程也不能改变原先固定 200 的风暴伤害圈；修正模型或动画同样不能修复几何覆盖。

另一种方案是在选中敌人的位置创建半径 200 的风暴。这可以保留较小聚怪范围，但需要定义施法时锁定位置、目标消失后的行为以及远端效果的生命周期；现有剑圣自身旋转也无法准确表现远端伤害。当前说明和历史重设计文档描述的是原地旋转、周围群体伤害，因此选择保留自身圆心。

以上是推理排除与设计取舍，不代表已将每个替代方案实现并实测。

## 最小修改

1. `tdOrcBladestormRadius()` 改为固定 780，保持独立技能配置。
2. 原生 `presetCastRange` 引用同一函数，使目标选择距离与伤害半径一致。
3. 技能说明明确自身周围 780、范围固定且不受装备射程加成影响。
4. 不修改运行时的圆心、伤害节奏、路线过滤及状态清理。维持持续 2.5 秒、每 0.5 秒一次、每秒 70 伤害、冷却 9 秒；完整覆盖的配置伤害预算仍为每目标 175。
5. 随后的单变量诊断确认默认 Slow 自动施法条件不适用于本图行军敌人，保留 `setAlwaysAutocast(1, true)`。这是原生自动施法配置修复，不添加脚本轮询施法系统。

测试保留对 CD、持续时间和 tick 的断言，更新半径为 780，并断言 5 次 tick 的配置预算和每目标总伤害预算 175。新增窄产物检查复用已有 MPQ/W3A 读取器，确认实际打包 A132 的原生施法距离为 780，及固定范围说明已进入技能对象。

## 验证命令与待验证项

按顺序执行，最终地图只使用项目唯一入口构建部署：

```powershell
tools\Run-WurstChecks.bat
build-and-deploy-test-map.bat
python tools/VerifyBladestormAbilityArtifact.py ExampleMap.w3x
```

初次交接时未执行上述命令，由主线程统一检查构建。本次更新已收到 0126、0137 实机证据，以及扩展后的风暴产物检查 PASS：A132 的 `Slo3` 等级 1、列 3 为布尔编码 `(0, 1)`。未追加声称尚未提供的正式版最终检查结果。

0126 实机证据：第 4 波结束、等待第 5 波时，截图显示 `STORM EFFECT`、`STORM START`、`FORCED order=true`，以及五行 `TICK hits=2,2,3,3,4`。这次使用原生 `slow` 定向订单，未直接调用脚本施法函数。结果说明进入了原生施法事件和脚本状态，并完成五次存在有效敌人目标的伤害调用；目标数不是目标身份追踪，不能说明同一目标吃满五次，更不能认定每个目标实际扣血 175。该截图未捕捉到 spin 帧。

此前第 2 波未出现 FORCED 日志，不足以判定原生能力失效：一次性诊断选目标范围为 740，而低级怪可能在普攻射程内先被击杀，未进入诊断范围。直到更高血量波次才得到上述有效触发证据。

0137 单变量诊断已完成：保持预置塔、位置与日志，移除一次性 forced 计时器，仅将 Slow 的 `setAlwaysAutocast(false)` 改为 `true`。等待第 3 波时截图出现自然 EFFECT、START 和五次 `hits=0`，证明自然施法与空命中周期均能完成；低波敌人可能已被普攻击杀，这是解释假设。等待第 5 波时，同屏出现两组自然 EFFECT、START，各自五次 tick，命中数分别为 `1,2,3,3,4` 与 `3,2,1,1,1`。由此确认无需 forced 的自然重复施法及有效敌人伤害调用，故保留 true 为修复。

此对照支持“默认 Slow 自动施法条件不适用于本图行军敌人”。本地元数据与编辑器字符串只证明字段是“总是自动施放”，并未逆向证明默认条件严格限定为“只对正在攻击的目标施放”，文档不作这种扩大结论。

后续仍需确认：旋转动画可见；每目标实际扣血；范围边界与其他路线不误伤；施法中死亡/卖塔能够清理；正式图通过正常升级获得 6B 后的自动施法。0137 的预置塔诊断不能代替正常建造升级流程验证，也不能代替移除诊断后的正式版验证。

范围扩大后的圆面积约为原先的 15.2 倍，每目标伤害预算虽然保持不变，总伤害会随覆盖敌人数增加。至少观察连续两波的实际清怪表现，记录是否覆盖整段敌群；平衡性尚未确认。装备射程不会扩展技能范围，这是明确规则。

## 可复用经验与可提炼技能

- 在高台塔防中，先比较合法塔位与真实道路/配置路点的距离，再讨论近身技能特效或伤害参数。
- 由一种原生技能提供触发、由脚本提供伤害时，把原生目标选择范围和脚本伤害范围放入同一规则函数。
- 分开验证三个层次：源码配置、打包对象、实机行为。产物正确不等于自动施法或效果已经可用。
- 可提炼“技能表现与有效覆盖诊断”：确认圆心与范围 → 合法位置/路线距离 → 原生目标条件 → 实机轨迹与伤害 → 群体伤害平衡。
