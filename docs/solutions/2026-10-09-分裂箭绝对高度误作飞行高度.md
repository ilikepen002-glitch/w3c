# 分裂箭绝对高度误作飞行高度

## 现象与影响范围

0218 诊断图中，弓箭 6A 对三个暂停的高血量靶执行原生攻击，订单返回 true，塔有抬弓动作；3.0 至 4.9 秒的八帧截图未能清楚辨认箭矢。三个靶间隔 96，画面接近重叠，也限制了视觉判断。仅凭这组截图不能认定所有箭都未创建。

随后只读检查发现脚本分裂箭把绝对世界高度传入了相对地面的飞行高度接口。这是明确的 API 契约错误，影响 `tdLaunchArcherSplitArrowVisual` 创建的额外箭。原生主箭由单位物编配置驱动，不经过该 Fx 路径，不能把其不可见也归因于同一问题。

当前状态：独立方案审查 PASS，主线程已实施最小修复，类型检查和全部测试通过；正在通过唯一 BAT 构建同布局实机对照。新图箭矢表现尚未得到结果，不能宣称可见性已修复。

## 根因：绝对高度与相对高度接口混用

本地实现可直接确认以下契约：

| 调用 | 实际语义 |
| --- | --- |
| `vec2.withTerrainZ(offset)` | 返回地形高度加偏移，即绝对世界 Z |
| `new Fx(vec3, facing, path)` | 调用 `setZ(pos.z)`，将 Z 当飞行高度 |
| `Fx.setZ(z)` | 调用单位 `setFlyHeight(z, 0)`，即相对地面的高度 |
| `Fx.setXYZ(pos, true)` | 直接以 `pos.z` 设置飞行高度 |
| `Fx.setXYZ(pos, false)` | 先减去当前位置地形高度，再设置飞行高度 |
| `Fx.setXYZ(pos)` | 经 `unit.setXYZReal` 执行同样的地形高度扣除 |

原代码从塔坐标生成 `withTerrainZ(90)`，从目标坐标生成 `withTerrainZ(60)`，在绝对世界空间插值得到弹道。插值方式本身成立，但构造 Fx 时与每次更新时都将绝对 Z 作为相对飞行高度传入，重复计入了地形高度。

用项目已有 W3E 解码器读取实际地图，上述位置所在网格四角高度一致：

| 位置 | 地形 Z | 预期端点绝对 Z | 错误传入的飞行高度 |
| --- | ---: | ---: | ---: |
| 塔 `(-1696, 2016)` | −128 | −38，即地面以上 90 | −38 |
| 三个道路靶位置 | −256 | −196，即地面以上 60 | −196 |

本图的地形高度为负，因此错误并非简单地“飞得太高”，而是把负值传给飞行高度接口。箭可能被置于地面下，或受到原生高度钳制而靠近地表。这里的负高度行为仍是基于数据和契约的解释：尚未采集实机 `GetLocationZ`、假单位高度与引擎钳制结果，不声称已经证明每一帧实际渲染在何处。

## 与此前计时错误的关系

此前 `getCount()` 被误认为已执行次数，导致分裂箭首次更新就跳到终点并销毁。该问题已单独修为 `cb.progress()` 插值、`cb.isLast()` 清理，见《计时回调倒计数导致技能提前结束》。

计时修复恢复了中间帧，却没有改变这些帧使用错误飞行高度的事实。这是两层独立问题：一个决定效果持续多久、如何推进；另一个决定效果位于哪里。不能把二者合并成同一根因，也不能用一个问题的验证替代另一个。

本次没有通过换箭模型、放大效果、改变射速或调整游戏地形来掩盖坐标错误；这些方向没有被作为修复实施。0218 画面中三个靶接近重叠也只是观察限制，不足以解释已经确认的高度契约误用。

## 最小修复

仅修改项目侧 `tdLaunchArcherSplitArrowVisual`：

1. 使用 `new Fx(startPos.toVec2(), facing)` 创建 Fx。
2. 先 `setXYZ(startPos, false)` 放到正确绝对高度，再 `setFx(...)` 附加原箭模型。
3. 每个 tick 使用 `setXYZ(currentPos, false)`，将绝对插值位置转换成相对地形飞行高度。

保留原有端点偏移、模型、弹速、计时进度、伤害和目标选择逻辑。不修改 Fx 标准库，因为依赖接口本身提供了正确的绝对高度入口，错误在项目调用处。
