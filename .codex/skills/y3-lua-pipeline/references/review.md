# Lua 审查（合并官方 y3-lua-review）

1. 确定真实业务文件与入口。用 Lua 解析器或现有脚本检查语法，不用关键词计数代替解析。
2. 核对当前 lualib API、`meta/event.lua` 字段及调用时机。项目自定义事件不在引擎表里不代表错误。
3. 追踪重复初始化、玩家离开、重开、销毁后回调、目标失效、资源不足。本地 UI 与同步战斗/经济边界重点检查。
4. 检查 UI 完整路径和创建时机，以及点/句柄/ID/枚举的类型。`require`/`include` 由真实入口与热重载约定决定。
5. 问题报告给具体位置、触发条件、影响和证据。历史模式不能机械替换，例如 `is_alive` 未必等于“仍在游戏中”。
6. 纯审查不擅改；已授权修复则处理确定问题并定向验证，无需每项确认。API 存在性不能推出功能完整，未实测明确说明。
