# Warcraft III 地图快速试玩

确认实际运行的地图版本，完成用户要求的验证范围。检查通过、部署成功、载入开局、具体问题回归分别报告。

## 何时执行

任务开始时用户没有要求实机验证，默认只完成开发、检查、编译部署和离线产物核验，不启动或操作 Warcraft III，也不例行追问是否试玩。修复玩法、图标、模型或性能问题本身不等于要求实机验证；明确说明未实测即可，不因此阻塞开发交付。

用户后续明确要求试玩、进入游戏、实机复现或验证时，再执行本技能，已有明确请求无需重复确认。仅修改技能或文档时，不为验证这些文字启动游戏或重新编译地图。

## 决定是否构建

先读取项目 `AGENTS.md` 的协作门禁和验证要求，按当前会话授权执行。只要求进入已部署地图时，核实目标后直接进入；源码变更或要求重新编译时才运行对应检查与构建。已确认且未变化的路径、工具链和环境不重复扫描。

需要首次定位本机入口、构建/部署或处理文件锁时，读取 [本机与构建](references/local-build.md)。用户指定使用已打包的发布地图时，核对指定提交、名称及哈希，直接部署该地图，不以重编译覆盖它。

需要构建时遵守项目唯一入口 `build-and-deploy-test-map.bat`；项目检查与构建必须串行，等待检查进程全部结束。记录本次输出、部署路径和源/部署 SHA256，并确认一致。失败后保留错误，不启动旧图当作本次新版本。

## 电脑控制与默认入口

首次电脑操作前读取当前可用的 `computer-use:computer-use` 技能及其要求的 guidance、confirmations；底层工具规则决定可调用 API。需要启动器交接、窗口恢复、崩溃诊断时，读取 [电脑控制与故障恢复](references/ui-recovery.md)。

复用正确的现有窗口和菜单。每次操作遵守“一次观察、一次操作、立即刷新”：只用最新观察到的窗口、控件和坐标，不盲串快捷键，不固定要求两次截图或长等待。转场未完成时短暂等待再观察，不在空白面板重复按键。

下面快捷键由用户提供，作为默认入口；本次技能修改未实机验证。每个动作之后立即刷新，确认已到下一画面再继续：

| 当前画面 | 默认动作与核对 |
| --- | --- |
| 主菜单 | 按 L 进入局域网 |
| 局域网列表 | 按 C 打开创建游戏 |
| 地图浏览器 | 进入 Test，选本次正确地图，核对右侧详情标题/版本标记 |
| 地图确认页 | 按 C 创建房间 |
| 房间玩家槽位页 | 核对用户需要的玩家设置，按 Alt+S 开局 |
| 载入画面 | 等待进度完成，出现继续提示后按 Space |
| 地图内 | 等初始化完成，观察工人、资源、提示和目标行为 |

快捷键后无进展时，刷新并核对焦点和当前菜单，再按可见按钮恢复；房间有聊天框，不用裸 S 替代 Alt+S。默认单机基线无需把空守方槽填成电脑，Enemy 槽已有电脑。

详情 HHmm 标记不是唯一版本号。同名条目、同分钟或跨日标记歧义时，停止猜选，按 [本机与构建](references/local-build.md) 核对候选并清理已确认的旧项目测试图后刷新列表。

用户停止电脑控制或工具报告物理 Escape 停止时，立即停止 UI；只有用户之后明确要求恢复电脑操作才继续。查看源码或整理技能不代表恢复控制。

## 验证范围与交付

链路验证以载入、工人可操作、首波启动为界；bug 回归按复现条件检查，不自动扩展成通关。需要选工人、测试金币或升级复现时，读取 [玩法验证](references/gameplay.md)。

报告已完成的层级、运行版本证据、实际观察及未验证项。游戏加载后再改源码或覆盖磁盘文件，不会证明该局运行新版本；也不能由后来磁盘哈希反推此前已加载的版本。
