# Y3 地图开发

执行方式遵循仓库 AGENTS.md：用户已恢复并行执行，按独立职责分配文件所有权。Warcraft 构建入口不用于 Y3。

编辑器操作、Codex/MCP 接入、资源导入和热更新使用 [y3-editor-control](../y3-editor-control/SKILL.md)，先确认目标工程和当前工具能力，再执行修改。

- 以用户最新目标为准。完整可玩版本须有建造与成长、精灵培养、战斗、全程波次、胜负与可操作界面；三波演示或纯逻辑测试不能替代交付。
- 编辑器安装与地图源码分开。由编辑器创建标准工程，核实 header.project、地图目录和 script/main.lua；不凭猜测拼工程文件。
- 使用与本地版本兼容的官方 Lua 库，核对真实 API、参数、事件语义和数据格式。官方库不修改；先查内置能力，避免复制引擎系统。
- UI 只保存显示状态并提交意图。玩家资源、精灵、宿主、候选和波次在同步逻辑中校验与修改；随机数、费用和结果须保持同步。重复、过期或越权操作不能改变状态。
- 物编、场景和 UI 优先使用编辑器或官方开发工具。批量文件修改必须基于已验证模板/序列化工具并保留原字段，不臆造 JSON schema。
- 复用 Wurst 的玩法规则、数据与回归场景，明确原型数值与正式数值的差异；不承诺 MDX/BLP 或 Warcraft 原生行为直接兼容。
- 新图标使用 imagegen 技能，保留生成原图、提示词与项目内资源引用，并在实际 UI 尺寸检查清晰度。
- 先验证确定性规则和输入边界，再检查实际工程加载、UI 操作与完整战役胜负。离线测试通过不能表述为实机通过；发布与账号操作另按用户授权范围执行。
- 定时停止任务以明确时区和绝对时间为准；开始长任务前检查剩余时间，到点保存状态并停止，未完成目标不得标记完成。
