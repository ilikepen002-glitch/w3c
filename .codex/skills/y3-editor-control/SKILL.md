# Y3 编辑器操作

优先使用官方 MCP 完成可验证的工程操作。地图玩法架构仍由 y3-map-dev 负责。本项目按用户最新约定允许并行执行，各执行者限定修改范围；用户负责启动编辑器和游戏，除非后续改变约定，不重复启动程序。

## 先确认连接与工程

1. 发现当前会话中的 Y3 工具；未加载时读取 [Codex 接入](references/codex-integration.md)。端口可达、配置存在和工具实际可用是三个不同状态。
2. 获取当前服务的 tools/list，再调用只读工程信息接口；确认项目路径、地图 ID 与目标一致。服务返回“请先打开地图”时不能继续写入。运行时调用还需确认客户端槽位。
3. 针对任务只加载必要资料：[操作方法](references/editor-workflows.md)、[本项目路径与验证事实](references/local-project.md)、[官方文档阅读记录](references/manual-reading.md)。不要每次重读全部教程。

## 修改与核验

- 先核对编辑器未保存状态并保存，再备份将修改的对象；通过已验证 API 或真实模板修改。外部文件修改后调用对应热更新，读取日志/对象确认结果，最后保存。避免编辑器旧内存覆盖外部新文件。
- 参数以当前服务 schema 为准，教程中的历史工具名只供定位能力。HTTP 成功、JSON-RPC 成功仍可能包含业务错误；检查 isError、文本错误及实际输出。超时后的写入结果未知，先读回状态，不盲目重复导入或创建。
- Lua 业务源与部署目标分开；不只修改部署副本。资源导入须取得实际资源 ID 和元数据，不能仅复制 PNG 后宣布可用。
- 每次变更选择能证明结果的核验：字段读回、导入记录、编辑器截图、运行日志或实际交互。UI 截图不能证明按钮事件、多人同步或完整战役通过。
- 连接失败先核对项目、服务所属进程和日志；没有新证据不重复打开编辑器或尝试同一组点击。不可因界面无响应就断言权限不足。

## 交付口径

分别说明文件已修改、编辑器已加载、运行时已验证中的哪些已完成。技能或 MCP 配置写入不等于当前会话已发现工具；依赖未运行时保存工作并说明具体缺口，不把离线测试表述成实机通过。
