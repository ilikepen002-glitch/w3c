# 玩家文案

用于 tooltip、HUD、公告和错误提示。说明和备注都应帮助玩家上手或作出选择；每句话都要能回答“怎么用、有什么效果、付出什么、有什么必要限制”。不能改变玩家操作或判断的信息，删去或移到开发注释。

保留能帮助玩家决策的效果、用法、成本、目标、限制、关键数值及不可逆后果；简洁不等于隐藏伤害、冷却、价格、叠加规则或适用目标。

- 规则放在相关技能/操作上；导航按钮只说明目的地或用途，不重复命令卡/HUD 已展示的规则，也不每次打开页面都广播。
- 设计理由、内部计算口径和实现细节放在开发文档或注释。图鉴入口可写“查看技能、上阵或培养”，无需解释显示品质的计算过程。
- 错误提示说明发生了什么和下一步；资源损失/未扣除在相关时说明，不暴露记录 ID、版本检查等内部信息。诊断日志与玩家提示分开。
- 装备/技能先写主要效果，再写必要的触发、目标、冷却或叠加限制。对照实际目录数据及生效逻辑核对数值，删去“设计为”“用于填补”“按内部公式”等设计说明及重复强调；不要用含糊的“更强”替代可比较的关键数值。
- 难度选择只保留帮助选择的挑战描述和有意义的规则差异，不列生命倍率等内部调参。例如“敌人更强，适合熟悉玩法后挑战”，无需追加“生命倍率 ×1.25”。开局公告只给简短的下一步和必要当前状态；已有按钮或界面说明的内容不再连续刷屏。
- 全局文案整理先清点装备、技能、难度、HUD、帮助和公告的玩家可见入口；共用文案统一术语，并核对动态拼接后的完整句子。只清理展示文字和纯提示，不误删携带玩法行为的触发；开发日志仍保留诊断信息。
- 交付前以玩家视角读改过的字符串。仅在发现共用模板或相同根因时扩查关联文案，不因一次措辞修改普查所有 tooltip 或重设计玩法。
- 更新已过时的文字断言，保留底层玩法测试，不为满足旧断言保留面向开发者的文案。
